# Workflow

1. Read the source and existing T17 owner/contract before changing behavior.
2. Select one bounded leaf (at most five implementation files); split additional
   behavior into a linked slice without duplicating ownership.
3. Implement and run focused checks. Numerical/public-contract work receives
   coherent specialist agent review; routine work needs no repeated human gate.
4. Record exact results and remaining limitations. Do not mark a scientific,
   package or consumer obligation complete from a rename, source copy or toy test.
5. Run required native CI for the selected compiler profiles before merging.
6. Use immutable dependency revisions until release artifacts are qualified.
   Registry publication remains a separate explicitly authorized action.

Current task status may be pending, in progress, complete or blocked. Preserve
stable T17 aliases across repositories; external consumer completion is recorded
by the consumer owner and referenced here. Rollback is a normal revert or a
consumer pin rollback to an actually qualified revision, not a second core.
